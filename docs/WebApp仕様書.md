## 1. 概要

SF作品に登場するような宇宙インフラやイベント（太陽光の集光・送光、レーザ送電、スペースサンシェード、電源・排熱など）を、物理モデルに基づいて計算するWebシミュレータ。
ユーザーはモジュール（シム）を選び、パラメータを入力して結果を確認し、条件を変えた複数の計算結果を並べて比較する。

- 当面は「シミュレータとして遊ぶ」ことを目的とし、ミッション・スコアなどのゲーム要素は入れない。
- 特定のSF作品に基づくプリセットは、各シムが完成してから追加する。
- モジュール同士の連携（あるシムの出力を別のシムの入力に渡すこと）は将来対応とし、まずは各モジュールを独立して動かす。ただし、後で連携できるデータ構造にしておく（§7.3）。

**原子炉・遮蔽モジュール（新規）の範囲**
- 炉心の熱出力（入力）から、炉心の寸法と質量、燃料の消費、放射線（中性子・ガンマ線）の強さ、遮蔽の厚さと質量、停止後の崩壊熱を概算する。
- 遮蔽の方式は、影遮蔽（ブームで炉心を離す場合を含む）、全方向遮蔽、天体の表面での配置（地上・地下・半地下）を扱う。遮蔽材には、現地のレゴリスやレゴリスのコンクリートを使え、地球から運ぶ質量と現地で調達する質量を分けて出す。
- 燃料（ウラン235、ウラン233、プルトニウム239）と冷却材（水、ヘリウム、液体金属など）を選べる。冷却材の放射化による熱交換器の放射線も扱う。
- 当面は核分裂炉だけを扱う。将来は核融合炉にも対応する。
- 電源・排熱モジュールは、原子炉を「熱源」として簡単に扱う。将来モジュールを連携させるときに、原子炉・遮蔽モジュールの結果を熱源として渡せるようにする。
各モジュールの計算内容の妥当性検証と修正は別途行い、モジュールごとの仕様書（md）として出力する。

## 3. 技術構成・公開方式

参考リポジトリ TypingCard_DD と同じ構成をベースにする。

| 区分 | 採用技術 |
|---|---|
| 言語 | TypeScript |
| UI | React 19 |
| ビルド | Vite |
| スタイル | Tailwind CSS v4 |
| テスト | Vitest（物理計算の単体テストを重視する） |
| Lint | oxlint |
| グラフ | SVG描画のチャートライブラリ（Recharts を第一候補とする）【仮決定】 |
| 数式表示 | KaTeX（解説欄で数式を表示する）【仮決定】 |
| 並び替え | dnd-kit（マウスとタッチの両方でドラッグできる）【仮決定】 |
| 画像保存 | html-to-image（カードをPNGで出力する）【仮決定】 |
| ルーティング | ハッシュルーティング（`#/sim/solar-beaming` など。GitHub Pages で直リンクやリロードをしても404にならない） |
| 公開 | GitHub Pages。`main` への push で GitHub Actions が lint → test → build → deploy を実行する |

- ビルドは `base: './'`（相対パス）にする。リポジトリ名のサブパスで配信されるため。
- アプリのバージョンは `package.json` の `version` から取り込み、ヘッダに表示する。

### 3.1 物理計算に関する方針

- **計算は純粋関数に分ける。** 各モジュールの計算ロジックは、UI（React）に依存しない関数（入力値 → 出力値・警告・グラフ用系列）として実装し、Vitest で検証する。
- **内部の値はすべてSI単位で持つ。** m、kg、s、W、K、rad などで統一し、画面の入出力でだけ単位を換算する（§5.4）。
- **物理定数は1か所にまとめる。** 光速、ステファン＝ボルツマン定数、AU、太陽輝度などを共通の定数ファイルで定義し、出典を書いておく。
- **想定外の入力に備える。** 0除算、負の値、指数のオーバーフロー、NaN や Infinity が出たときは、結果欄に数値ではなくエラーや警告として表示する。
- **物理的にありえない条件では警告を出す。** 元仕様書にある判定（理論限界の超過、排熱温度 < 環境温度、など）は、計算関数が警告として返し、UIに表示する。
- **テストの内容。** 各モジュールについて、手計算や文献値で確かめた代表ケースを数件、テストとして持つ（妥当性検証の結果をそのままテストに使う）。

## 4. 画面構成

### 4.1 共通レイアウト

```
┌──────────────────────────────────────────┐
│ ☰  SFインフラシミュレータ v0.1      [言語]* │ ← ヘッダ（上部に固定）
├──────────────────────────────────────────┤
│                                          │
│            メインコンテンツ               │
│                                          │
└──────────────────────────────────────────┘
 * 言語切替ボタンは将来用。当面は表示しない（§8）
```

- ヘッダ：ハンバーガーメニュー、アプリ名「SFインフラシミュレータ」、バージョン。
  - 画面イメージPDFではタイトルが「シミュレータシミュレータ」と重複しているが、誤記なので「SFインフラシミュレータ」とする。
- ハンバーガーメニューを押すと、左からドロワーが開く。

### 4.2 ハンバーガーメニューの項目

1. トップ
2. シミュレータ一覧（登録されているモジュールを自動で並べる）
   - 太陽光集光・送光
   - レーザ発振・送電
   - サンシェード・展開軌道
   - 電源・排熱
   - 原子炉・遮蔽
3. 使い方
4. 更新履歴

今いる画面の項目は強調表示する。

### 4.3 トップ画面

- アプリの簡単な説明。
- モジュールの一覧をカードで表示する（名称、1〜2行の説明、アイコン）。押すとそのシム画面に移る。【仮決定】

### 4.4 使い方画面

- 基本操作（カードの追加・複製・並び替え・削除、グラフ軸の設定、JSON/画像の保存と読込）を説明する。
- データはタブを閉じると消えることを明記し、JSONエクスポートを勧める。

### 4.5 更新履歴画面

- バージョンごとの変更点を新しい順に並べる。データはソース内で管理する。

### 4.6 シム画面（メインコンテンツ）

画面イメージPDFの「1.コンテンツ部分イメージ」に対応する。

```
┌ シム名 ───────────────────[JSON読込][全件保存][全削除]┐
│ ▼ パラメータや計算の解説（アコーディオン・折りたたみ可）   │
├─────────────────────────────────────────────────────────┤
│ [＋ 新しい計算を追加]                                     │
│ ┌ 計算結果カード A ────────────────────────────┐         │
│ └──────────────────────────────────────────┘         │
│ ┌ 計算結果カード B ────────────────────────────┐         │
│ └──────────────────────────────────────────┘         │
└─────────────────────────────────────────────────────────┘
```

- **解説欄**：モジュールの目的、入力パラメータの意味、計算式（KaTeX）、前提・制約を表示する。
  - 初期状態（開くか閉じるか）は保留。
  - 当面は仮の簡単な説明文だけを入れる。詳しく正確な解説は、そのモジュールの計算部分ができてから書く。
- **＋ボタン**：入力値を初期値にした新しいカードを、リストの先頭に追加する。
- **画面全体の操作**：JSONの保存と読込は、カード1枚ずつが基本（§4.7）。手間を減らすため、そのシムの全カードをまとめて1つのJSONに保存する「全件保存」も用意する。読込ボタンは、1枚分のファイルも全件分のファイルも受け付ける。全削除は確認ダイアログを出してから実行する。
- そのシムにカードが1枚もないときは、初期値のカードを1枚自動で作る。【仮決定】

### 4.7 計算結果カード

画面イメージPDFの「2.計算結果欄イメージ」に対応する。

```
┌──────────────────────────────────────────────────┐
│ ⠿  [タイトル（編集可）            ]  [複製][⋯]   │ ← ⠿ = ドラッグハンドル
├──────────────────────────────────────────────────┤
│ ▼ 入力・出力                                       │
│   ┌ 入力 ─────────────┐ ┌ 出力 ──────────────┐   │
│   │ 太陽距離 [1.0 ][AU▾]│ │ 放射照度 E  1.23e5 W/m²│ │
│   │ 基数 N  [100 ][基 ] │ │ Suns        90.1      │ │
│   │ …                   │ │ ⚠ 警告メッセージ       │ │
│   └─────────────────┘ └────────────────────┘   │
│ ▼ グラフ                                           │
│   X軸 [距離 d ▾] 範囲[1e3]〜[1e7] [対数▾]          │
│   Y軸 [放射照度 E ▾] [対数▾]                       │
│   （グラフ本体）                                     │
└──────────────────────────────────────────────────┘
 [⋯] メニュー：JSONで保存 / 画像で保存 / 上へ / 下へ / 削除
```

#### タイトル
- その場で編集できる。初期値は「計算 1」「計算 2」…のような連番。
- 複製したときは「（元のタイトル）のコピー」にする。

#### 入力・出力欄（アコーディオン）
- 入力値を変えると即座に再計算する（ボタンを押す必要はない）。
- 入力欄の種類：
  - 数値：`1.5e7` のような指数表記でも入力できる。単位を選べるパラメータには単位セレクタを付ける。
  - 選択（Enum）：例「発振器の方式」「推進方式」「配備位置」。選ぶと関連するパラメータにプリセット値を入れる。その後も手で値を上書きできる。
  - 真偽（Boolean）：例「凹面鏡かどうか」。トグルスイッチで切り替える。
  - 一覧（表）：例「遮蔽の層（材料と厚さ）」「混合材料の成分（割合と調達先）」。行の追加・削除・並び替えができる。行数の上限と下限はモジュールが決める。
- 選択肢によって不要になるパラメータは、表示しないかグレーアウトする（例：化学レーザのときだけ反応エネルギー密度を表示する）。
- **入力と出力の切り替え**：計算の向きを選ぶと、入力だったパラメータが出力（計算結果）になるものがある（例：原子炉の熱出力を「自動で決める」、サンシェードを「目標から構成を出す」、遮蔽を「基準から厚さを出す」）。
  - 出力になった欄は、同じ場所に計算結果を「自動」の印付きで読み取り専用で表示する。一覧（表）では、出力になるセルだけを読み取り専用にする。
  - それまでの入力値は消さずに持っておき（JSONにも保存する）、入力に戻したときに元の値に戻す。
- 入力が範囲外や不正なときは、その欄を赤枠にし、理由を表示する。出力欄にはエラーを表示する。
- 出力欄には、値、単位、警告（⚠）、エラー（✖）を表示する。出力には、数値のほかに文字（例：「日陰中で決まる」）と表（例：材料・成分ごとの質量の内訳）がある。表は出力欄の中に表の形で表示し、画像保存にも含める。
- 計算中は、出力欄に「計算中」の表示を出す（§9）。
- 各パラメータ名にマウスを乗せる（スマホではタップする）と、短い説明が出る。【仮決定】

#### グラフ欄（アコーディオン）
- **軸はカードごとに自由に選べる。**
  - X軸：そのモジュールの数値入力パラメータから1つ選ぶ。一覧（表）の中の数値も選べる（例：「遮蔽の1層目の厚さ」）。その時点で出力になっているパラメータは選べない。範囲（最小〜最大）、点数、線形/対数を設定する。
  - Y軸：そのモジュールの数値出力から1つ選ぶ（出力になったパラメータを含む）。文字と表の出力は選べない。表の中で比べたい値は、モジュールが別に数値の出力としても出す。線形/対数を設定する。
  - グラフは、X軸以外の入力をカードの現在値に固定したまま、X軸のパラメータだけを範囲内で動かして計算する（パラメータスイープ）。
  - 現在の入力値に当たる点を、マーカーで強調表示する。
- **配列を出すモジュールの場合**（例：サンシェードの減光率の時系列、原子炉の中性子のエネルギー分布と崩壊熱の時間変化）、X軸の選択肢にその配列のX軸（時間、エネルギーなど）を加え、モジュールが返す配列をそのまま描画する。
- X軸の範囲の初期値は、現在値の 1/10 〜 10倍、点数50、対数軸とする。【仮決定】
- 計算できない点（エラーになる点）はグラフに描かない（線が途切れる）。

#### カードの操作
| 操作 | 内容 |
|---|---|
| 複製 | 入力値、グラフ設定、折りたたみ状態をそのままコピーし、元カードのすぐ下に追加する |
| 並び替え | 左上のハンドル（⠿）をドラッグして入れ替える（マウス・タッチ両対応）。キーボード操作やスマホでの誤操作対策として、メニューに「上へ／下へ」も用意する |
| JSONで保存 | そのカード1枚分をJSONファイルとしてダウンロードする |
| 画像で保存 | そのカード（タイトル、入出力、グラフ）をPNGとしてダウンロードする。折りたたんだ欄は画像に含めない |
| 削除 | 確認後に削除する |

> 画面イメージPDFではグラフ欄の左上の「◯」を並び替えのハンドルとしていたが、カード全体を動かす操作なので、ハンドルはカードのタイトル行の左端に置く。【仮決定】

## 5. データ仕様

### 5.1 保存方針

| 場面 | 振る舞い |
|---|---|
| 画面のリロード | カードは残る |
| タブやウィンドウを閉じる／端末を再起動する | 消える（許容） |
| 長期保存したいとき | JSONエクスポートを使う |

上の振る舞いを満たすため、ブラウザの **sessionStorage** に保存する。入力のたびに保存する（短い遅延をおいてまとめて書き込む）。

### 5.2 JSONエクスポート形式（案）

```json
{
  "app": "sf-infra-simulator",
  "formatVersion": 1,
  "exportedAt": "2026-11-02T12:00:00Z",
  "moduleId": "solar-beaming",
  "moduleVersion": 1,
  "cards": [
    {
      "id": "c_8f3a…",
      "title": "火星L1から艦艇へ",
      "inputs": { "d_sun": 1.52, "N": 1000, "is_concave": true },
      "inputUnits": { "d_sun": "AU" },
      "graph": { "x": "d", "xMin": 1e3, "xMax": 1e7, "xScale": "log", "points": 50, "y": "E_target", "yScale": "log" },
      "ui": { "ioOpen": true, "graphOpen": true }
    }
  ]
}
```

- `inputs` はSI単位の値を保存する。`inputUnits` は表示単位の選択だけを保存する。
- 出力値はJSONに保存しない（読み込んだときに再計算する）。
- カード1枚分のファイルも、全件分のファイルも同じ形式にする（`cards` 配列の要素数が違うだけ）。
- 読み込んだカードは、ファイル内の順番を保ったまま、リストの先頭に追加する（＋ボタンと同じ位置）。
- `moduleId` が今のシムと違うファイルは、エラーを表示して読み込まない。
- `moduleVersion` が古いファイルは、マイグレーション関数で新しい形式に変換してから読み込む。モジュールの仕様が変わったときのため。
- 知らないパラメータは無視する。足りないパラメータは初期値で補う。

### 5.3 画像出力

- PNG形式。ファイル名は `<モジュールID>_<カードタイトル>_<日時>.png`。
- 背景を含め、画面の見た目どおりに出力する。

### 5.4 単位と数値の表示

- 単位を選べるパラメータの例：
  - 距離：m / km / AU
  - 角度：rad / mrad / µrad / deg
  - 時間：s / 日 / 週 / 月 / 年
  - 波長：m / µm / nm
  - 温度：K（必要なら℃も）
- 出力値は有効数字4桁で表示する【仮決定】。絶対値が 10⁻³ 未満または 10⁶ 以上のときは指数表記（`1.234×10⁷`）にする。
- 出力の単位も、大きい値は見やすい単位で表示できるようにする（例：面積 m² / km²、質量 kg / t）。

## 6. レスポンシブ対応（PC優先・スマホ対応）

| 項目 | PC（幅768px以上） | スマホ（幅768px未満） |
|---|---|---|
| メインコンテンツ | 中央寄せで最大幅を設定（例：1100px） | 画面いっぱいに表示 |
| カード内の入出力 | 入力と出力を左右2列に並べる | 縦に並べる（入力 → 出力） |
| グラフ | 高さ約320px | 高さ約220px。軸の設定は折りたためるパネルに入れる |
| 並び替え | ハンドルのドラッグ | ハンドルの長押しドラッグ、またはメニューの「上へ／下へ」 |
| 数値入力 | 通常の入力欄 | `inputmode="decimal"` で数字キーボードを出す |
| ヘッダ | 固定表示 | 固定表示（高さを抑える） |

画面設計についての提案：

## 7. 拡張性（モジュールの追加）

### 7.1 モジュール定義

各モジュールを次のような定義オブジェクトとして登録する。新しいモジュールは「フォルダを1つ追加して、レジストリに1行足す」だけで、メニュー、トップ画面、カード、グラフ、JSON入出力がすべて動くようにする。

```ts
interface SimModule {
  id: string;              // 'solar-beaming'
  version: number;         // JSON互換性のためのバージョン
  name: string;            // 表示名
  summary: string;         // トップ画面用の短い説明
  explanation: string;     // 解説欄（Markdown + 数式）
  inputs: ParamDef[];      // 数値 / Enum / Boolean / 一覧（表）。単位、初期値、範囲、表示条件を持つ
  outputs: OutputDef[];    // 出力の定義（型、単位、主要出力かどうか）
  presets?: PresetDef[];   // Enum を選んだときに一括で入れる値（シナリオのプリセットを含む）
  compute(inputs): ComputeResult;   // 純粋関数
  migrate?(old): Inputs;   // 旧バージョンのJSONを変換する
}

// 入力の型
type ParamDef = NumberParam | EnumParam | BooleanParam | TableParam;

interface NumberParam {
  kind: 'number';
  key: string;
  unit: UnitDef;           // 内部単位と、選べる表示単位
  default: number;
  min?: number; max?: number;
  visibleWhen?: (inputs) => boolean;
  // 省略時は常に入力。'output' を返すと、計算結果を表示する読み取り専用の欄になる
  role?: (inputs) => 'input' | 'output';
}

interface TableParam {
  kind: 'table';
  key: string;             // 例：'shieldLayers'
  columns: ColumnDef[];    // 各列は 数値 / 選択 / 真偽。数値の列も role を持てる
  minRows: number;
  maxRows: number;
  defaultRows: Row[];
  visibleWhen?: (inputs) => boolean;
}

// 出力の型
type OutputValue =
  | { kind: 'number'; value: number }                                // 単位は OutputDef に持つ
  | { kind: 'text'; value: string }                                  // 例：'日陰中で決まる'
  | { kind: 'table'; columns: string[]; rows: (number | string)[][] } // 例：質量の内訳
  | { kind: 'series'; x: number[]; y: number[] };                    // 例：崩壊熱の時間変化

interface ComputeResult {
  outputs: Record<string, OutputValue>;  // 出力になったパラメータも同じキーで入れる（例：outputs.Q_r）
  warnings: Message[];     // 警告（計算は続ける）
  errors: Message[];       // エラー（出力は無効）
}
```

- 一覧（表）の入力は、JSONに配列として保存する（例：`"shieldLayers": [{"mat": "W", "t": 0.048}, …]`）。グラフのX軸の候補には、表の数値のセルを `shieldLayers[0].t` のような名前で並べる。
- `role` が 'output' のパラメータは、計算関数が同じキーで `outputs` に値を入れて返す。

## 9. 非機能要件

- **計算の動かし方**：
  - すべてのモジュールの計算を、画面とは別の処理（Web Worker）で動かす。重い計算の間も画面が固まらないようにする。
  - 入力を変えてから 150 ms 待ち、そのあいだに次の入力がなければ計算する。計算の依頼ごとに番号を付け、古い依頼の結果が後から届いた場合は捨てる。
  - カードの結果を先に計算して表示し、グラフはその後で計算して描く。計算中は、カードとグラフに「計算中」の表示を出す。
- **速さの目標**：

| 対象 | 目標 |
|---|---|
| カードの結果（すべてのモジュール） | 50 ms 以内 |
| グラフ50点（太陽光、レーザ、電源・排熱、サンシェード） | 200 ms 以内 |
| グラフ50点（原子炉・遮蔽で最適化を含む場合） | 1秒以内 |

- 重い最適化（遮蔽の厚さ、ブームの距離など）は、総当たりではなく、大まかに調べてから黄金分割法などで詰める方法を使う（原子炉・遮蔽モジュール仕様書 §4.12）。
- サーバとの通信はしない。すべてブラウザ内で動く静的サイトにする。
- 対応ブラウザは、最新版の Chrome / Edge / Safari / Firefox。
